2. Variables and the basic data types

A variable is a name standing for a region of memory that holds data temporarily while the program runs.

In C you must declare a variable's data type explicitly before you use it. The basic types are:

  • Integers: int (typically 4 bytes on modern 32-bit/64-bit machines).
  • Floating point: float (typically 4 bytes) and double (typically 8 bytes).
  • Characters: char (always 1 byte), holding a single character or a small integer.
⚠️ An important note about machine architecture
The actual size of C's data types (except char, which is always 1 byte) is not fixed: it depends on the CPU architecture (8-bit, 16-bit, 32-bit or 64-bit) and on the operating system and compiler. You can consult the standard specification in the C type system documentation, and the details of the data models (LP64, ILP32 and friends) under arithmetic types on cppreference.com. For example, int is 2 bytes on 8-bit/16-bit embedded microcontrollers (such as the Arduino Uno) but 4 bytes on a modern x86/ARM CPU. To write portable code, always measure with the sizeof() operator rather than hard-coding a number.

3. Reading keyboard input with scanf

To take data typed by the user, we use the scanf function. Note that you have to pass the address of the variable by putting the & (address-of) operator in front of its name. Without the &, the program hits a Segmentation Fault or undefined behaviour (Undefined Behavior).

ℹ️ Three terms that just appeared
Address — every variable lives in a memory cell, and that cell has its own number, like a house number. &age means "the house number of the variable age". scanf needs the house number rather than the value, because its job is to write into that cell, not read from it.

Segmentation Fault — the operating system catches your program touching memory that does not belong to it and stops the program immediately. In the Terminal you will see Segmentation fault (core dumped). It sounds alarming, but it is actually the friendly kind of failure: it stops right at the mistake.

Undefined Behavior — considerably worse. The C standard says "I make no promises about this case", so the program may work today, break next week, or fail only on someone else's machine. There is no error message at all. Most of the warnings in this lesson exist to keep you away from exactly this.
{{CODE:scanf_demo.c}}

Common mistakes with scanf:

  • Forgetting the & — for int, float, double and char you must pass the address with &. Arrays (for example char name[50]) are the exception, because an array name already decays into a pointer to its first element.
  • Buffer overflow with %s — if the user types a string longer than the array, the data overwrites memory that does not belong to it, which is a serious security bug. Always bound it with %49s (for an array of size 50).
  • A leftover \n in the buffer after %d / %f — when you press Enter after typing a number, the newline character stays in the stdin buffer. If the next scanf("%c") has no leading space, it reads that \n instead of waiting for a new character. The fix: use scanf(" %c", &c) with a space before %c.

4. The complete format specifier table

Format specifiers tell printf and scanf which data type is being written or read. The full reference lives at cppreference.com — fprintf.

Specifier Data type Description Example
%d int Signed integer (decimal) printf("%d", -42);
%u unsigned int Unsigned integer printf("%u", 42u);
%ld long Signed long integer printf("%ld", 100000L);
%lld long long Very long integer (64-bit) printf("%lld", 9000000000LL);
%f float / double Floating point (printf accepts both float and double) printf("%.2f", 3.14);
%lf double Used in scanf to read a double (for printf, %f is enough) scanf("%lf", &d);
%e float / double Scientific notation printf("%e", 0.00123); → 1.230000e-03
%c char A single character printf("%c", 'A');
%s char* / char[] A string (terminated by \0) printf("%s", "Hello");
%p void* A pointer address (in hex) printf("%p", (void*)&x);
%x unsigned int Integer in hexadecimal printf("%x", 255); → ff
%o unsigned int Integer in octal printf("%o", 8); → 10
%% — Prints a literal percent sign printf("100%%"); → 100%

5. Type modifiers and sizeof

C provides type modifiers — extra keywords that change the size and value range of the basic integer types. Full details at cppreference.com — Arithmetic types.

  • short — a short integer, typically 2 bytes (at least 16-bit per the C standard).
  • long — a long integer, typically 4 bytes (32-bit) on Windows and 8 bytes (64-bit) on 64-bit Linux/macOS.
  • long long — a very long integer, always at least 8 bytes (64-bit) per the C99 standard.
  • unsigned — stores non-negative values only (0 and up), doubling the positive range compared to signed.
  • signed — stores both negative and positive values (the default for int).

💡 When should you use stdint.h?
When you need code that behaves identically on every platform (portable code), especially in embedded programming, network protocols or binary file handling. Types such as int32_t and uint8_t guarantee an exact size regardless of the CPU architecture. See cppreference.com — Fixed width integer types.

6. Constants, enums and type casting

A. Constants: const vs #define

C has two common ways to define a constant — a value that never changes:

  • const — creates a constant variable with an explicit data type, checked by the compiler. Safer, and easier to debug.
  • #define — a preprocessor macro that substitutes text before compilation. It has no data type and occupies no memory, but it can cause subtle bugs if you are not careful.

That is why the general rule is: use const for constants, and reach for #define only when you really need it.

C. Type casting

Casting means converting a value from one data type to another. C supports two forms:

  • Implicit casting — the compiler converts automatically when it needs to, following the "smaller type → larger type" rule (integer promotion). For example int → double.
  • Explicit casting — the programmer states it directly with the (new_type)value syntax.
